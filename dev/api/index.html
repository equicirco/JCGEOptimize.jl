JCGEOptimize — Module
JCGEOptimize

Optimization around JCGE equilibrium models for policy design and parameter optimization, with multiple objectives, constraints, and interchangeable backends.

Model evaluators delegate equilibrium calculations to JCGERuntime and return model outcomes to this package. Search backends share decision, objective, constraint, validation, and evaluation-history interfaces.

source
JCGEOptimize.DecisionVariable — Type
DecisionVariable(name; lower, upper, initial=(lower + upper)/2)

A continuously varying model input with finite bounds and an initial candidate. The evaluator receives decisions as a named tuple using these names.

source
JCGEOptimize.Objective — Type
Objective(name, measure; sense=:min, scale=1.0)

A scalar objective extracted from the evaluator's outcome. sense is :min or :max. Search backends minimize signed values divided by scale; records retain the original values and units.

source
JCGEOptimize.OutcomeConstraint — Type
OutcomeConstraint(name, measure; lower=-Inf, upper=0, tolerance=0, scale=1)

Bounds on a scalar outcome, including equality constraints when lower == upper. tolerance is in the outcome's original units. Feasibility allows that tolerance on either side; backend residuals are then divided by scale.

source
JCGEOptimize.OptimizationProblem — Type
OptimizationProblem(decisions, evaluator; objectives, constraints=[],
                    isvalid=outcome->true, on_error=:throw)

Describe an outer optimization problem. evaluator(named_decisions) performs a model evaluation and returns its outcome. isvalid must accept only outcomes whose equilibrium status and residuals satisfy the model's numerical criteria. Rejected outcomes never enter the optimum or Pareto set.

Unexpected exceptions propagate by default. With on_error=:record, ordinary exceptions become failed evaluation records. Interrupts always propagate.

source
JCGEOptimize.EvaluationRecord — Type
EvaluationRecord

One model evaluation: named decisions, objective and constraint values in their original units, scaled constraint violations, model-validity status, feasibility, diagnostic message, elapsed seconds, and the evaluator's outcome. Evaluators should return compact outcomes rather than retain a whole solver model per call.

source
JCGEOptimize.evaluate — Function
evaluate(problem, values; id=1) -> EvaluationRecord

Evaluate one bounded candidate. A numerically valid model can still be infeasible for the outer outcome constraints. Nonfinite objective or constraint values are rejected, regardless of the validity callback.

JCGEOptimize.GridSearch — Type
GridSearch(axes)

Evaluate the Cartesian product of one nonempty axis per decision. The initial candidate is evaluated first and is not repeated if it also occurs on the grid. This deterministic backend provides a comparison for heuristic searches.

source
JCGEOptimize.MetaheuristicsBackend — Type
MetaheuristicsBackend(algorithm_factory; seed=1, max_evaluations=1000, failure_penalty=1e6)

Optional Metaheuristics.jl search backend. Import Metaheuristics to activate it. The factory receives the configured Metaheuristics.Options and must use those options, for example options -> Metaheuristics.ECA(N=20, options=options).

The initial candidate and all failed evaluations count towards the hard model evaluation budget. Each call creates a new algorithm with its own seeded RNG. Rejected evaluations are passed to the algorithm using the finite positive failure_penalty for scaled minimization objectives and constraint violations. This prevents undefined arithmetic in algorithms using fitness-weighted averages. The original failure records are retained and can never qualify as feasible.

source
JCGEOptimize.OptimizationResult — Type
OptimizationResult

Search results containing the problem, all evaluation records, termination reason, and backend metadata. best is the best feasible evaluated candidate for one objective, or nothing when none is feasible or several objectives were declared. pareto contains feasible nondominated candidates. These are search results, not certificates of global optimality or equilibrium uniqueness.

source
JCGEOptimize.optimize — Function
optimize(problem, backend; callback=record->nothing) -> OptimizationResult

Run an outer search. callback receives each completed evaluation in order. Only candidates passing both model validation and outcome constraints enter the reported optimum or nondominated set.

source
JCGEOptimize.evaluation_rows — Function
evaluation_rows(result)

Return a vector of flat named tuples suitable for tabular export. Decision, objective, constraint, and violation columns have explicit name prefixes; failed evaluations remain in the table with their status and diagnostic message.
